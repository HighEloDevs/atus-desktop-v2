# 0003 — Projetos portáteis em SQLite

O ATUS precisa reabrir análises com dados, configurações e rascunhos, inclusive depois de mover o arquivo original de importação. Consideramos armazenar um único JSON em cada projeto e centralizar o catálogo em um banco local. A estrutura híbrida mantém pontos ordenados e relações explícitas, com JSON para opções de interface. A descoberta na pasta padrão continua possível sem o histórico local.

O arquivo .atus usa application_id 0x41545553 e user_version 2. As tabelas são project, analyses, datasets e data_points. As posições preservam a ordem e NULL representa incerteza ausente. Configurações e rascunhos são JSON, cujo formato é governado pela versão do esquema. Os scripts numerados em `src/desktop/migrations/` são embutidos no binário. Projetos novos executam o esquema inicial e os scripts seguintes antes da primeira gravação, sem gerar backup. A migração v1 → v2 adiciona um índice de tipos de análise, guarda backup SQLite exclusivo ao lado do original e valida a integridade antes do commit.

Gravações usam uma transação SQLite e comparam o estado anterior com o estado no disco dentro da transação de escrita. Uma divergência bloqueia a gravação e a interface oferece Salvar como. Arquivos novos são preparados na pasta de destino e publicados sem sobrescrever um arquivo existente. O aplicativo usa o journal padrão do SQLite e arquivos fechados podem ser copiados individualmente.

O histórico fica no armazenamento local da WebView. A tela inicial combina o histórico com os arquivos descobertos em Documentos/ATUS/projects. A importação do JSON legado será uma entrega separada. Renomear, arquivar e excluir projetos estão em `0008-project-management.md`; a tela inicial agora lista os recentes e os projetos da pasta padrão em tabelas separadas.
